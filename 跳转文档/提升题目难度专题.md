# 提升题目难度专题

**提升难度是任务本身够难而不是故意刁难模型**，是真实工作场景中人会遇到的困难而不是人为设置的卡点；**在出题时把模型当成自己的同事或实习生**。在工作或科研场景中，人类在完成任务的时候往往不知道完成这件事的正确路径，很多时候需要自己摸索方法或者需要从团队的只言片语（群聊，规章制度，过往任务沉淀的约定俗成的规矩）整合信息。

### prompt部分

1. 从自身工作出发而不是从AI那里找灵感，优秀的题目往往非常贴合真实的工作环境。
2. 合理不在prompt中提供部分信息，合理在部分关键信息做模糊处理：比如模型需要通过自己的推理甚至自己的判断才能找到完成任务的关键数据。比如一些专家会详细介绍每一份附件的内容，详细写出计算的公式和考点。可以适当进行留白让模型自行检索或自行寻找信息。
3. 目前模型做的好的部分：按照固定的流程完成即可完成，当题目有清晰的完成路径或者推理路径时，模型完成度比较高；所以专家在出题可以适当模糊完成路径，不用描述的非常清晰，可以改为给模型留下可推理的线索，或者鼓励模型自己作出决策。
4. 尝试尽可能扩大项目范围/覆盖完整项目周期：

   1. 优先选择原本就需要多人或多团队密切协作的大型项目，并把相关合作方或上下游工作纳入同一任务。

   > 例如，一个产品发布项目可以同时涉及用户研究、竞争分析、定位设计、预算规划、发布材料和风险审查。但这些工作必须围绕同一个产品和同一组关键决策展开，不能只是若干独立任务的集合。

   1. 不要只截取项目中的单一环节，应尽量覆盖从发现问题到最终交付、验证和修订的全过程。

   > 例如：
   > 
   > - 投资项目：前期访谈与行业研究 → 商业分析 → 财务尽调 → 法务尽调 → 风险判断 → 投资材料撰写 → 多轮审查与修订。
   > - 经营改进项目：发现问题 → 收集数据 → 提出假设 → 设计分析或实验 → 验证假设 → 制订改进方案 → 深化方案 → 形成落地计划。
   > - 科研项目：文献梳理 → 研究问题定义 → 方法设计 → 数据处理 → 结果分析 → 稳健性检查 → 论文材料撰写 → 审稿意见回应。
   > 
   > 各阶段必须共享信息并相互影响，不能只是按顺序排列的独立流程。

### 附件部分

1. **提升数据的获取难度**：真实的工作中往往有很多脏数据，真正有用的信息往往藏在噪声下；目前很多专家提供的数据太干净，真实工作环境中的原始数据的数据格式、数据质量、数据内容往往并不标准甚至充满错误。
2. **增加合理矛盾**，在关键数据/刚需信息部分制造矛盾点：不同数据源的数据需要模型自行找到证据判断权威性；任务具有时间跨度的时候，不同时间点的数据模型需要根据当前时间找到正确的数据（比如国家统计局数据修订，法律条款的更新）；不同口径的计算结果不同，模型需要找到正确的计算口径
3. 设置需要模型需要从不同的附件中整合信息的题目，优秀的题目中的关键信息往往分散隐藏在不同的附件中，模型只有真的读懂了附件中的内容，把零散的信息拼凑出来才能完成任务。在现实生活中往往也是这样，完成领导任务所需要的信息不会只存在在一个文件中，往往需要人从不同的文件中拼凑零散的信息才能得到完整的信息
4. 目前模型做的不好的部分：需要自己做决策；给模型各方的意见需要模型判断

### 标答部分

标答鼓励适当的开放性，不必保证只有一个正确答案。真实世界中的复杂工作往往允许多种合理方案，核心是最终结果是否符合目标、证据是否充分、决策是否合理以及成果是否可用。

### 提升轮次

1. 增加模型需要交付的产物的数量和种类
2. 联网搜索信息
3. 涉及不同规则的大量数据的清洗和处理
4. 让模型自己进行选择和判断

### 提升难度相关的tips

> 希望专家读到以下思路时，去回忆真实的场景出题。而不是按我们的方式从零去虚构一个题目。

#### **多证据冲突，而且"哪个证据有效"不能靠简单的最新日期判断**

这是我认为比较有效的一类。

例如同时给：

- 正式制度 v3；
- 一个日期更晚但尚未生效的 v4；
- 一封管理人员邮件，对某一条规则做临时豁免；
- 后续又有一封邮件撤销豁免；
- Excel Summary 是最新生成的，但底层用的是旧快照；
- 一个签字文件时间较早，却具有最高权限；
- 前台界面显示 Complete，但底层依据的文件是草稿级别；
- 一条记录后续被撤销。

模型不能做“全文搜索 → 找到一句话 → 使用”。

它必须自己建立：

**证据 → 权限 → 生效时间 → 适用对象 → 当前状态**

这样的状态模型。

这里尤其有效的一种设计叫**显著性反转**：

> 最醒目、最像答案的材料，是错误的。
> 
> 真答案需要综合几个不那么显眼的证据才能得到。

---

#### **总任务很明确，但真正关键的“判断标准”需要模型自己推出来**

Prompt 可以非常清楚地告诉模型最终要做什么，难点不需要靠故意把题目写模糊。

真正有难度的是：

> 用户告诉了模型“要选谁、要判断什么、要做什么决策”，但没有直接告诉模型“这次决策真正应该重点看什么”。

例如任务要求从几个供应商中选一家。

材料里可能大量介绍：

- 产品质量；
- 报价；
- 公司规模；
- 获奖情况；
- 综合评分；
- 甚至已经做了一张很完整的供应商能力排行榜。

但结合项目当前情况后，真正决定成败的可能是：

**谁能够稳定按期交付。**

而“交付能力”本身又没有直接做成一个评分字段，只能从历史延期次数、订单积压、产能利用率、临时停产记录等材料里自己推出来。

模型很容易沿着材料已经搭好的评价框架继续分析，最后选出一个“综合能力最强”的对象。

问题在于：

> 它回答得很完整，但解决的不是当前最关键的问题。

这类题考察的是模型能否从总体任务进一步恢复出：

**当前瓶颈 → 真正判断标准 → 应该读取哪些证据 → 最终决策**

而不是材料给什么指标，模型就分析什么指标。

---

#### **同一批对象同时命中多个规则，而且规则之间没有固定的优先级**

简单的规则题通常是：

**A 优先于 B，B 优先于 C。**

这种模型很容易处理。

更难的是，规则优先级会随着“同时命中了哪些条件”发生变化。

例如：

- 同时符合 A、B 时，先处理 A，再处理 B；
- 同时符合 B、C 时，B 覆盖 C；
- 同时符合 A、C 时，反而 C 优先；
- 同时符合 A、B、C 时，不再沿用前面的规则，而触发一个特殊组合规则；
- 某些对象还有单独的例外；
- 例外又只在特定时间或状态下生效。

这时候规则关系已经不是简单的：

**A > B > C**

而是：

**对象当前状态 → 命中规则组合 → 确定处理顺序 → 判断覆盖关系 → 再检查例外**

真正容易出错的地方是：

> 模型可能把每条规则都理解对了，但组合到一个具体对象上以后，处理结果仍然是错的。

这类设计很适合审批、税务、优惠资格、保险理赔、价格政策、库存处理、风险分类等任务。

---

#### **正确答案可以是“没有答案”“不能继续”或者“当前条件下无解”**

模型有一个很明显的倾向：

> 用户让我解决一个问题，我就应该给出一个结果。

如果问题非常简单，模型通常能识别矛盾。

例如直接问：

> 有没有一个数字同时大于10又小于5？

模型当然知道没有。

但如果同样的矛盾被埋进一个复杂任务的中间环节，模型就更容易忽略。

例如在一个真实的采购任务里同时存在：

- 预算上限；
- 最低技术标准；
- 最晚交付日期；
- 最低采购量；
- 供应商资格要求；
- 地域限制。

每一个条件单独看都很正常。

模型可能认真做完价格比较、供应商评分、风险分析，最后推荐一个“最优方案”。

但真正需要检查的是：

> 有没有任何一个方案能够同时满足所有硬约束？

答案可能是：**一个都没有。**

类似的情况还包括：

- 当前证据不足以确定唯一结论；
- 两个必要条件互相冲突；
- 缺少一个不可替代的输入；
- 所有候选对象至少违反一条硬规则；
- 当前流程根本没有达到进入下一阶段的条件。

这种题最有效的地方在于：

> 让模型完全可以继续算，而且还能算出一个看上去非常漂亮、非常合理的结果。

真正的难点是它能不能意识到：

**这一步原则上就不应该继续往下算。**

---

> 使用以上tips的时候注意不要把“假陷阱”变成“真漏洞”
