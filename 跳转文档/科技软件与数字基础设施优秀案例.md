 | **考点** |  | 考点一：制品与SBOM身份（满分2分）
2分：版本、发布记录、两个数量和SBOM来源均准确
1分：版本正确且数量仅一项偏差不超过5
0分：版本或SBOM身份错配
考点二：OSV筛查范围（满分2分）
2分：三个数量均准确并说明查询时点
1分：其中两个数量正确
0分：把包命中数当作唯一漏洞数或数量明显错误
考点三：漏洞严重度分布（满分2分）
2分：五档数量全部准确且合计251
1分：一档偏差不超过2且合计说明正确
0分：严重度分布明显错误或把包数当严重度条目数
考点四：OSV与KEV交叉（满分2分）
2分：交叉方法、结果0、目录时点和限制均写明
1分：结果正确但限制说明不完整
0分：声称存在KEV命中或因0直接放行
考点五：CVE-2024-9264适用性（满分2分）
2分：适用版本、权限、前提、影响和列示的修复版本均准确
1分：适用性正确但遗漏权限或前提
0分：把11.0.0判为不受影响或错误引用修复版本
考点六：CVE-2025-3260不适用判断（满分2分）
2分：适用范围和修复11.6.1+security-01均准确
1分：识别不适用但未写依据
0分：把该CVE计入11.0.0或忽略反例核查
考点七：CVE-2025-4123未决判断（满分2分）
2分：准确引用修复分支、XSS条件和现有材料的适用性缺口
1分：结论方向谨慎但未列配置核对
0分：无依据作出确定适用或不适用结论
考点八：SBOM关系与可达性限制（满分2分）
2分：三项限制均写明并设置补证动作
1分：识别关系缺口但仅覆盖一至两项限制
0分：把142个包全部认定为运行时可利用
考点九：三类安全证据分层（满分2分）
2分：三类证据各自回答的判断问题清楚且不相互替代
1分：区分两类但仍有一处混用
0分：用组件命中替代产品适用性或用KEV替代漏洞判断
考点十：版本发布结论（满分2分）
2分：结论由CVE-2024-9264和升级策略共同支撑；duckdb缺失仅作临时缓解，不改变版本淘汰
1分：结论正确但升级目标或临时缓解关系不清
0分：批准11.0.0或只关闭duckdb后长期放行
考点十一：整改与复核路径（满分2分）
2分：每项有责任角色、状态和关闭证据
1分：覆盖至少四项但责任或证据不全
0分：只有泛化升级建议
考点十二：发布门禁审核表（满分2分）
2分：审核表中的版本、筛查结果、漏洞适用性、处理状态和关闭条件与备忘录一致

0分：审核表与备忘录冲突、缺少关键结论或出现虚构漏洞

 | **作答思路** |  | 先绑定发布制品和SBOM，再复核组件筛查、严重度与KEV交叉。产品公告单独用于判断版本适用性，SBOM关系不足的部分列为待核。最后把阻断、非阻断、未决项和复核条件同步写入备忘录与门禁审核表。 | 

 | **标准答案-文字（如有）** |  | Grafana 11.0.0的产品公告已给出明确阻断项；组件筛查和KEV交叉只能用于排序，不能替代版本适用性与运行时可达性判断。CVE-2025-3260对目标版本不适用，CVE-2025-4123按现有材料仍需补证。结论：暂停推广11.0.0，迁移到当前受支持且已修补的版本，再以新制品、新SBOM、现网配置和回归结果重新评审。 |
